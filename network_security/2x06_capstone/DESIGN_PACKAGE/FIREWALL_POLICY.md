# FIREWALL POLICY: LogiCorp Gateway

## 0. Network reference

### Gateway interfaces

| Interface | Role | Note |
|---|---|---|
| `eth1` | WAN (Internet egress) | IP provided by the ISP/modem (lab: `10.42.166.24/16`, gateway `10.42.0.1` — see audit §2) |
| `eth2` | 802.1Q trunk to the switch | Carries no IP, only the VLAN sub-interfaces |
| `eth2.10` / `.20` / `.30` / `.50` / `.60` | One sub-interface per zone | Each zone communicates with the others **only through the gateway** |
| `wg0` | WireGuard VPN tunnel | `10.8.0.1/24` |
| `eth0` | Hosting provider's link-local link | Out of LogiCorp scope (see §5) |

### Addressing plan

Convention: the 3rd octet of the subnet = the VLAN ID. `.1` = gateway, `.2–.49` = static, `.100–.199` = DHCP.
Global internal space: `10.50.0.0/16` (used for documentation only, **never** as the target of an ACCEPT rule).

| Zone | VLAN | Subnet | Gateway | DHCP | Static | Interface |
|---|---|---|---|---|---|---|
| Office PC | 10 | `10.50.10.0/24` | `10.50.10.1` | `.100–.199` | — | `eth2.10` |
| Finance PC | 20 | `10.50.20.0/24` | `10.50.20.1` | `.100–.199` | — | `eth2.20` |
| Guest Wi-Fi | 30 | `10.50.30.0/24` | `10.50.30.1` | `.100–.199` | — | `eth2.30` |
| Database | 50 | `10.50.50.0/24` | `10.50.50.1` | none | DB: `10.50.50.50` | `eth2.50` |
| DMZ | 60 | `10.50.60.0/24` | `10.50.60.1` | none | FTP: `10.50.60.40` | `eth2.60` |
| VPN | — | `10.8.0.0/24` | `10.8.0.1` | — | per peer (see VPN_DESIGN.md) | `wg0` |

No DHCP in the Database and DMZ zones: they only contain servers with fixed IPs, and a rogue machine plugged into these VLANs does not get an address automatically.

## 1. Default Policies

| Chain | Traffic concerned | Target policy | Justification |
|---|---|---|---|
| INPUT | Traffic destined for the gateway itself | **DROP** | Zero Trust: only the VPN, SSH via VPN and infrastructure services (DHCP) are open |
| FORWARD | Traffic crossing the gateway (zone → zone) | **DROP** | No zone talks to another without an explicit rule |
| OUTPUT | Traffic generated by the gateway | **DROP** (after a transitional ACCEPT phase) | The gateway hosted a backdoor (a cron job that "phones home"): its own outbound traffic must be controlled too |

OUTPUT stays on ACCEPT during deployment (steps 1 to 7 of the IMPLEMENTATION_PLAN). It only switches to DROP last, once the gateway's legitimate outbound flows have been identified in the logs.

## 2. Rules

Notation: `iif` = input interface, `oif` = output interface.
"To Internet" is always written `oif eth1`, never `destination any`: otherwise a "Guest → any 443" rule would also allow Guest → Database on 443.

### 2.1 INPUT (to the gateway)

| # | Source | Destination | Proto/Port | Action | Justification |
|---|---|---|---|---|---|
| I1 | any | gateway | established/related state | ACCEPT | Replies to connections already allowed. First: it is the highest-volume traffic, and it avoids breaking ongoing sessions |
| I2 | any | gateway | invalid state | DROP | Packets that belong to no known connection (scans, forged packets) |
| I3 | `lo` | gateway | any | ACCEPT | Internal machine communication (local services) |
| I4 | `iif eth1` (WAN) | gateway | UDP 51820 | ACCEPT | Only entry point from the Internet: WireGuard. Silent to anyone without a valid key |
| I5 | `iif wg0`, VPN admins `10.8.0.10–10.8.0.19` | gateway | TCP 22 | ACCEPT | SSH administration **only** via the VPN and **only** for admin peers (fixes ACC-02) |
| I6 | `iif eth2.10, eth2.20, eth2.30` | gateway | UDP 67 | ACCEPT | DHCP server for the user zones. Not in the DB/DMZ zones (no DHCP) |
| I7 | `iif eth2.*, wg0` | gateway | ICMP echo-request, limited to 5/s | ACCEPT | Internal diagnostics (ping of the gateway). Rate-limited against floods. Not open on the WAN side |
| I8 | any | gateway | any | LOG `"IN-DROP: "` (limited) | Trace of refused attempts before the DROP policy (MON-01) |
| — | | | | **policy DROP** | |

### 2.2 FORWARD (between zones)

| # | Source | Destination | Proto/Port | Action | Justification |
|---|---|---|---|---|---|
| F1 | any | any | established/related state | ACCEPT | Replies to allowed connections. Also allows the passive FTP data connections already associated |
| F2 | any | any | invalid state | DROP | Same as I2 |
| F3 | `iif eth1` (WAN) | FTP `10.50.60.40` | TCP 21 | LOG + DROP | Redundant with the policy, but explicit for traceability: cleartext FTP is never exposed to the Internet (fixes ACC-05). The dedicated log prefix makes attempts easy to spot |
| F4 | `iif eth2.60` (DMZ) | any | any | LOG + DROP | If the FTP server is compromised, it cannot **initiate** any connection: neither to Office/Finance/Database (lateral movement, NET-01) nor to the Internet (exfiltration). Its legitimate replies go through F1 |
| F5 | `iif eth2.30` (Guest) | `oif` ≠ `eth1` | any | LOG + DROP | Guest reaches no internal zone (fixes NET-02). Placed **before** F8 so that the isolation does not depend on the order of the access rules |
| F6 | `iif eth2.10` (Office) | `oif eth1` (Internet) | TCP 443, UDP+TCP 53 | ACCEPT | HTTPS browsing + DNS. UDP 53 = normal DNS queries, TCP 53 = large replies |
| F7 | `iif eth2.20` (Finance) | `oif eth1` (Internet) | TCP 443, UDP+TCP 53 | ACCEPT | Same as F6. Separate rule: per-zone counters and logs, and rights that can be changed independently |
| F8 | `iif eth2.30` (Guest) | `oif eth1` (Internet) | TCP 443, UDP+TCP 53 | ACCEPT | Same as F6. Guest has **only** this access |
| F9 | `iif wg0`, VPN accountants `10.8.0.100–10.8.0.149` | FTP `10.50.60.40` | TCP 21 | ACCEPT | FTP control channel, reachable only by accountants through the encrypted tunnel (fixes ENC-01 on the Internet) |
| F10 | `iif wg0`, VPN accountants `10.8.0.100–10.8.0.149` | FTP `10.50.60.40` | TCP 30000–30100 | ACCEPT | FTP passive range (`pasv_min_port` / `pasv_max_port` of vsftpd), where the files transit |
| F11 | `iif eth2.20` (Finance) | FTP `10.50.60.40` | TCP 21, TCP 30000–30100 | ACCEPT | Finance retrieves the invoices uploaded by the remote accountants |
| F12 | `iif eth2.10, eth2.20` | DB `10.50.50.50` | TCP `<DBMS port>` | ACCEPT | Only business workstations reach the database, and only on its service port (fixes NET-03). **Port to be confirmed in `db.conf`** (e.g. 5432 PostgreSQL / 3306 MySQL) |
| F13 | `iif wg0`, VPN admins `10.8.0.10–10.8.0.19` | `10.50.50.50`, `10.50.60.40` | TCP 22 | ACCEPT | Administration of the DB and FTP servers, from the admin VPN only |
| F14 | any | any | any | LOG `"FWD-DROP: "` (limited) | Trace of any unplanned flow: also helps discover a legitimate flow forgotten during deployment |
| — | | | | **policy DROP** | |

No "VPN → LAN as needed" rule: each VPN population reaches only what it needs (F9, F10, F13).
Port 80 is not open to workstations (HTTPS only). Accepted consequence: the few sites still on HTTP no longer work. If a business need appears, TCP 80 is added to F6/F7 only, not to Guest.

### 2.3 OUTPUT (sent by the gateway) — final target

| # | Source | Destination | Proto/Port | Action | Justification |
|---|---|---|---|---|---|
| O1 | gateway | any | established/related state | ACCEPT | Replies (SSH, WireGuard, ping) |
| O2 | gateway | `lo` | any | ACCEPT | Internal communication |
| O3 | gateway | `oif eth1` | UDP+TCP 53, UDP 123 | ACCEPT | DNS resolution and time synchronisation (NTP, essential for log correlation) |
| O4 | gateway | `oif eth1` | TCP 80, 443 | ACCEPT | System updates (`apt` uses HTTP mirrors) |
| O5 | gateway (UDP 67) | `oif eth2.10, eth2.20, eth2.30` | UDP 68 | ACCEPT | DHCP server replies |
| O6 | gateway | log collector (to be defined) | TCP 6514 (syslog TLS) | ACCEPT | Sends logs off the machine (MON-03) |
| O7 | gateway | any | any | LOG `"OUT-DROP: "` | Any unexpected outbound traffic (backdoor beacon, attacker tool) becomes visible |
| — | | | | **policy DROP** | |

Known limitation: O4 would let the backdoor's beacon through if it targeted a public IP over HTTP. OUTPUT filtering therefore does not replace removing the cron job (IMPLEMENTATION_PLAN, step 1). It complements it with logging.

### 2.4 NAT

| Table | Rule | Justification |
|---|---|---|
| nat / postrouting | `oif eth1` → masquerade | Internal zones use private IPs (RFC 1918), not routable on the Internet. The gateway replaces the source IP with its own on the way out |

There is **no port redirection** (DNAT) from the WAN: no internal service is published on the Internet.

## 3. Rationale for the rule order

1. **Established/related state first (I1, F1, O1)**: the vast majority of packets belong to an already-accepted connection. Handling them first is more efficient and guarantees that no rule added further down cuts an ongoing session.
2. **Invalid states next (I2, F2)**: inconsistent packets are discarded before any evaluation.
3. **Anti-lockout rules early (I4, I5)**: VPN and admin SSH access is evaluated before any blocking rule. A mistake further down cannot cut off the administrator.
4. **Explicit DROPs before ACCEPTs (F3–F5)**: the critical isolations (DMZ, Guest, FTP to WAN) do not depend on the absence of a rule. If someone later adds an overly broad rule, the isolation still holds.
5. **ACCEPTs from most general to most specific, grouped by source zone (F6–F13)**: easier to read and audit.
6. **LOG just before the policy (I8, F14, O7)**: only traffic that matched no rule is logged, which avoids drowning the logs in legitimate traffic. Rate limiting so that a flood cannot fill the disk.

## 4. Reference implementation (nftables)

```nft
#!/usr/sbin/nft -f
flush ruleset

define ADMINS     = 10.8.0.10-10.8.0.19
define COMPTA     = 10.8.0.100-10.8.0.149
define FTP        = 10.50.60.40
define DB         = 10.50.50.50
define DB_PORT    = 5432            # to be confirmed in /etc/logicorp/db.conf
define FTP_PASV   = 30000-30100

table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    ct state established,related accept                                    # I1
    ct state invalid drop                                                  # I2
    iif lo accept                                                          # I3
    iifname "eth1" udp dport 51820 accept                                  # I4
    iifname "wg0" ip saddr $ADMINS tcp dport 22 accept                     # I5
    iifname { "eth2.10", "eth2.20", "eth2.30" } udp dport 67 accept        # I6
    iifname { "eth2.*", "wg0" } icmp type echo-request limit rate 5/second accept   # I7
    limit rate 10/minute log prefix "IN-DROP: "                           # I8
  }

  chain forward {
    type filter hook forward priority 0; policy drop;
    ct state established,related accept                                    # F1
    ct state invalid drop                                                  # F2
    iifname "eth1" ip daddr $FTP tcp dport 21 log prefix "WAN-FTP: " drop  # F3
    iifname "eth2.60" log prefix "DMZ-OUT: " drop                          # F4
    iifname "eth2.30" oifname != "eth1" log prefix "GUEST-LAT: " drop      # F5
    iifname { "eth2.10", "eth2.20", "eth2.30" } oifname "eth1" tcp dport { 53, 443 } accept   # F6-F8
    iifname { "eth2.10", "eth2.20", "eth2.30" } oifname "eth1" udp dport 53 accept           # F6-F8
    iifname "wg0" ip saddr $COMPTA ip daddr $FTP tcp dport { 21, $FTP_PASV } accept           # F9-F10
    iifname "eth2.20" ip daddr $FTP tcp dport { 21, $FTP_PASV } accept                        # F11
    iifname { "eth2.10", "eth2.20" } ip daddr $DB tcp dport $DB_PORT accept                   # F12
    iifname "wg0" ip saddr $ADMINS ip daddr { $DB, $FTP } tcp dport 22 accept                 # F13
    limit rate 10/minute log prefix "FWD-DROP: "                          # F14
  }

  chain output {
    type filter hook output priority 0; policy accept;   # switches to "drop" at step 8
    ct state established,related accept                                    # O1
    oif lo accept                                                          # O2
    oifname "eth1" udp dport { 53, 123 } accept                            # O3
    oifname "eth1" tcp dport { 53, 80, 443 } accept                        # O3-O4
    oifname { "eth2.10", "eth2.20", "eth2.30" } udp sport 67 udp dport 68 accept   # O5
    # O6: add the syslog collector once its address is defined
    limit rate 10/minute log prefix "OUT-DROP: "                          # O7
  }
}

table ip nat {
  chain postrouting {
    type nat hook postrouting priority 100;
    oifname "eth1" masquerade
  }
}
```

F6 to F8 are grouped here for readability. In production, splitting them per zone gives separate counters (`nft list ruleset` shows per-rule counters if `counter` is added).

## 5. Limitations related to the lab environment

- The container does not have `CAP_NET_ADMIN` (audit §4): this ruleset cannot be loaded on the lab target. It describes the target state of the LogiCorp gateway.
- `eth0` (link-local) and ports 3000/3001 (openvscode-server, ttyd) belong to the school's infrastructure. On a lab host, applying the INPUT DROP policy without an exception for `eth0` would cut off console access. They are out of scope for the LogiCorp scenario.
